# 8002 HTTP/2 复用 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 8002 公网代理端口在 ALPN 协商出 `h2` 时用 HTTP/2 CONNECT 多路复用承载隧道，协商不到时两端都保持现有 HTTP/1.1 / SOCKS5 行为。

**Architecture:** 服务端在现有 `tls.createServer` 上宣告 `ALPNProtocols: ['h2','http/1.1']`，`alpnProtocol === 'h2'` 的解密 socket 直接交给内置 `http2.createServer()` 的 `connection` 事件；每个 `CONNECT` 流独立连一次下游 8001。客户端在 `protocol=http` + TLS 时用独立 ALPN 上下文建一条（最多两条）h2 会话，把每条本地连接映射成一个 CONNECT 流，并用 reader/writer 垫片接进现有 `relay()`。

**Tech Stack:** Node 内置 `http2`（服务端零新依赖）；客户端 Python 3 + `h2`(hyper-h2，纯 Python) + asyncio。

**Spec:** `docs/superpowers/specs/2026-10-18-8002-http2-design.md`

## Global Constraints

- 不新增配置项、不改后台 UI、不动 8001/8003。
- 纯 TCP 模式（`socks5_tls="0"`）不启用 h2；不做 h2c。
- SOCKS5、HTTP/1.1 CONNECT、认证（主凭据 + 临时凭据）、attacker 限频、证书 pin、下游凭据剥离行为保持不变。
- CONNECT 头只发 `:method`、`:authority`、（有凭据时）`proxy-authorization`；**不得**发 `:scheme` / `:path`。
- 客户端新增依赖仅 `h2>=4.1`；`client/build.sh` 必须同步 `--include-data-files=h2_upstream.py=h2_upstream.py`。
- 注释与日志风格跟现有代码一致（中文注释/日志、`logger`/`console`），不新增英文注释堆砌。
- 项目规则：代码改动等用户验证后再提交，本计划**不执行 git commit**。

## Review Focus

1. 老客户端完全不发 ALPN 连新服务端：SOCKS5 与 HTTP/1.1 CONNECT 必须照旧可用（Task 1 测试）。
2. 老服务端（协商不到 h2）：新客户端降级后功能不变，且不会反复探测（Task 2/3 测试）。
3. CONNECT 若带上 `:scheme`/`:path`，Node 服务端会 `RST_STREAM(PROTOCOL_ERROR)`（Task 2 断言发送头集合）。
4. 单流 `SO_LINGER`/`abort()` 不得破坏共享 TLS 连接（Task 2 断言 `transport.abort()` 只重置本流，会话仍可开新流）。
5. h2 路径的认证与凭据剥离必须与 1.1 一致（407 且下游收不到 `proxy-authorization`）（Task 1 测试）。
6. 大包流控不死锁、发送缓冲有界（Task 2 测试）。
